# 생산관리 준비된 화면 보관 구현·검증

2026-09-15. 구현 기준 `20658c4`. 운영 배포와 최종 확인은 아래 배포 기록에 추가한다.

## 구현

- 기존 session 경로를 유지하고 `VITE_INSTANT_PAGE_ROUTES`로 새 경로를 메뉴별 선택한다. 빈 목록은 기존 보관 정책으로 돌아간다.
- 새 `instantPageResources.js`는 조회 준비와 화면 적용을 분리한다. 모델과 observations를 같은 revision으로 묶고, 배경 준비는 표시 중인 revision을 교체하지 않는다. 저장 명령은 비동기 권한 검사 전에 표시 기준을 복사한다.
- 기본 모델은 메뉴 이동과 구독 해제 뒤에도 유지한다. 선택 날짜/탭별 key, 64MiB 모델 soft budget, route별 최대 8개 key, 상세 설정별 resource, session clear를 적용한다. 실제 탭 전체 heap의 64MiB 제한을 뜻하지 않는다.
- 이탈 후 30초가 지나면 listener를 해제한다. 재방문은 마지막 확인본을 먼저 표시하고 최신 자료를 확인한다. 입력·포커스·모달이 있으면 변경 안내를 제공한다.
- 메뉴 모듈을 현재 본문 표시 후 순서대로 준비한다. 데이터 준비는 **이미 받은 snapshot만 사용**한다. cache miss를 정상 빈 데이터로 바꾸지 않고, 사용자가 진입하면 일반 조회로 전환한다.
- 생산 날짜, 원료 단계, 통계 기간/탭별 모델을 분리했다. 원료의 실제 탭 렌더를 기다리도록 수정했고 준비된 통계 탭에 날짜입력용 300ms debounce를 적용하지 않는다.
- 메인 순수 모델 준비와 방문 시 자동 알림을 분리했다. 준비만으로 자동 알림을 작성하지 않는다. 실제 방문의 알림 평가와 마감 직전 검증은 유지한다.
- 설정 8개 영역의 실제 값도 각각 보관한다. 기존 필드별 서버 변경 검사를 유지하며 설정 저장 후 보관 모델을 무효화한다.
- 조회 실패·권한 거부·세션 변경·늦은 응답·준비 중 진입 경합을 처리한다. 같은 데이터의 metadata 알림으로 새 경로 전체를 다시 그리지 않는다.
- 발주 삭제의 콤마 연산자 오류를 별도로 수정했다. 실제 버튼 경로의 fixture 검증을 추가했다.

## 계획에서 실측 후 선택한 범위

전 메뉴에 새로운 네트워크 선조회를 하는 대신, 이미 받은 데이터로만 준비하도록 제한했다. 방문하지 않을 메뉴의 Firestore reads를 늘리지 않기 위한 선택이다. 새 Functions/Scheduler/서버 요약은 추가하거나 켜지 않았다.

계산 원본과 과거 로그를 잘라내는 쿼리 변경, 새 index, FIFO 역산 변경, 가상 목록/worker는 이번 구현에 포함하지 않았다. 현재 보관/준비 방식으로 검증 환경의 표시 목표를 충족했으며, 불필요하게 재고 계산 범위를 변경하지 않는다. 향후 더 큰 운영 데이터에서 목표를 넘는 메뉴는 별도 병목 측정 후 이 작업들을 적용한다.

**완전 cold·처음 보는 데이터·임의 긴 통계 기간이 네트워크와 무관하게 300ms에 열린다는 보장은 하지 않는다.** 이전 데이터 표시와 서버 최신 확인은 별도다. 모든 직원 PC의 최종 성능 인수와 월 과금 무증가까지 완료했다고 표현하지 않는다.

## 자동 검증

- 프런트 회귀 127개: 기존 101개 + 새 준비/보관/실제 화면/설정/발주 삭제/경합/flag 회귀. 배포 직전 실행 결과를 확인한다.
- 실제 Firebase SDK + 격리된 `demo-fant-readpath` emulator 통합 7개 통과. 다른 client의 B를 배경 준비한 뒤 A 화면 기준 저장이 차단되는 검증 포함.
- `npm run build`, `git diff --check` 통과. 운영 DB에서 테스트 저장·삭제는 실행하지 않았다.
- 증거: `output/instant-regression-tests.txt`, `output/instant-core-tests.txt`, `output/instant-integration.txt`, `output/instant-build.txt`.

## 브라우저 측정

`scripts/previewPerformance.mjs 20658c4`로 기준판/후보판을 각각 localhost:4301/4302에 구성한다. 실제 브라우저에서 nav button과 하위 tab/section을 조작하고 본문 표시 후 두 프레임까지 측정한다. Firestore는 50ms/request의 메모리 fixture이며 운영 서버에 연결하지 않는다.
