# 부족재고 통합 알림 — 2026-11-06

사용자 요청: 부족재고를 한 줄로 묶고 클릭하면 모달에서 품목별로 확인. 같은 부족은 반복 알림을 내지 않으며 기존 재고·마감 로직과 실제 처리 알림 유지.

## 변경 범위

- `src/pages/main.js`, `src/layout.js`: 메인 요약 한 줄과 상단 부족재고 버튼. 개별 최소재고 알림은 기본 로그 패널에서 제외하고 전체보기·히스토리 원본은 보존.
- `src/utils/stockAlertsView.js`, `src/style.css`: 종류·품목 검색, 현재/최소/부족 수량 및 단위, 입고 예정, 재고 화면 이동, 개별·표시 항목 확인. 모바일에서는 품목별 카드로 표시.
- `src/domain/stockAlerts.js`, `src/services/stockAlerts.js`, `src/services/autoLogs.js`: 품목 ID별 부족 상태 전이와 공통 확인 기록. 기존 `activityLogs`만 사용하며 재고 컬렉션, 차감·입고·발주, 권한, 마감 판정 및 Firestore Rules는 수정하지 않음.

## 반복 방지

같은 부족 상태는 날짜가 바뀌거나 화면을 다시 열어도 새 알림을 만들지 않는다. 새로 부족해진 품목, 정상으로 회복한 뒤 다시 부족해진 품목, 같은 부족 기간 중 처음 0 이하가 된 품목만 새 미확인 알림으로 표시한다. 확인 처리는 읽었다는 표시이며 실제 부족 상태를 없애지 않는다.

기존 일별 `minStock:alert` 로그 중 품목별 최신 기록의 확인 상태를 이어 쓴다. 새 상태는 `details.stockAlert`의 key/sequence/status/previousId로 기록하며 결정적 문서 ID와 생성 전용 트랜잭션으로 동시 관찰 중복을 막는다. 정상 회복은 시스템 확인 상태의 조용한 전이 기록이며 직원의 처리 완료로 표시하지 않는다. 과거 로그를 삭제하거나 일괄 확인하지 않는다.

모달 확인 직전에 서버에서 재조회하여 수량·최소재고·알림 식별자가 바뀌면 자동 확인하지 않고 목록을 갱신한다. 표시된 부족 알림의 acknowledged 계열 4개 필드만 기존 확인 API로 수정한다. 숨겨진 검색/종류 항목과 재포장·입고 차이 등 처리 알림은 함께 확인하지 않는다.

최소재고 기준은 이전 코드와 동일하다. 계란/원료/봉투/부품 설정값, 활성 영양제 5봉을 사용한다. 원료 합계는 열린 재고만 사용하며 화면은 kg, 과거와 새 로그 details는 g 기준을 유지한다. 예정 입고는 부족 수량에서 빼지 않는다.

## 유지 사항과 한계

- 자동 재포장 확인, 실제 입고 수량 차이, 동결 부족 작업, 입고예정 도래, 부품 교체 예정, 마감 차단·경고는 유지.
- 기존 사양의 '최소재고 매일 반복'은 이번 사용자 요청으로 대체한다. 현재 코드에서는 최소재고가 생산 로그로 분류돼 있었으므로 두 로그 패널 밖 공통 요약에 둔다.
- 읽기 실패/알 수 없는 수량은 정상 회복으로 기록하지 않는다.
- 회복은 앱이 재고 상태를 관찰할 때 기록한다. 앱이 전혀 관찰하지 못한 사이에 회복과 재부족이 모두 끝난 경우 중간 상태를 추정하지 않는다.
- 기존 기록을 호환하기 위해 최초 조회는 `activityLogs` 중 minStock 이력을 읽는다. 신규 컬렉션/인덱스/백엔드 배포는 없다. 이전 버전을 열어둔 탭은 새로고침해야 일별 발행이 멈춘다.
