## 집계 계약

### 제품 생산

- productions: 유효 상태(active/completed), 생산일이 조회기간 및 오늘 이내, received=true, 유효 확정 수량·단위가 모두 있어야 한다.
- 생식: 최신 receivedTotalPacks를 팩으로 집계. 입력량·예상 박스·과거 outbox revision을 더하지 않는다. 과거 확정 수량 누락은 역산하지 않고 미확인으로 표시한다.
- 동결 생산: receivedFreezeType과 receivedFreezeQty로 빵판/동결판을 구분한다.
- frozenLogs: active인 포장 기록의 현재 수량. componentsSnapshot이 있으면 세트 조립으로 분리하고 sampleSetLogId가 있는 구성품 차감은 제외한다.
- 현재 마스터가 세트인데 과거 구성 스냅샷이 없으면 유형 미확인으로 분류한다.
- 생산 카드 또는 포장/조립 기록 1개를 해당 단계의 1건으로 본다. 다른 단계·단위를 합산하지 않는다.
- 간격은 조회기간 내 서로 다른 생산일 사이 n-1개 간격의 단순 평균. 마지막 생산일도 조회기간 내 기준이다.

### 원료 수급

- 외부 입고의 기준 원본: 원육 meatLogs.frozenIncoming, 봉투 bagLogs.incoming, 계란 eggLogs.in, 영양제 supplementLogs.in.
- 예정·재고 문서를 물량에 추가 합산하지 않는다. 전처리·재포장·수동조정·취소/삭제는 제외한다.
- 원육은 기록된 g를 kg로, 다른 품목은 기록 단위(장/개/봉)로 표시한다. 오늘의 박스 환산값으로 과거 물량을 재계산하지 않는다.
- 수량·날짜 이상은 확인 사항으로 표시하고 합계/평균에서 제외한다. 누락·미확인을 0으로 대체하지 않는다.
- 간격은 기간 내 서로 다른 입고일 사이 기준. 같은 날 여러 입고는 물량/건수를 유지하며 간격에서는 한 날짜로 계산한다.
- 마지막 입고는 조회 종료일까지의 기록을 읽는다. 기간 전 입고만 있으면 날짜·경과일을 표시하고 기간 수량은 확인 불가로 둔다.
- 입고예정 완료 코드는 당일을 입고 기록일로 저장하므로 실제 도착일이 보장되지 않는다.

### 입고예정 사전 등록

- schedules.status=completed이고 완료 처리일(KST)이 조회기간인 완료건이 표본이다. 직접 입고·취소·미완료는 제외한다.
- 사전 등록일수 = 최종 예정일 − 최초 등록일(createdAt, KST).
- 완료처리 소요일수 = 완료 처리일(completedAt, KST) − 최초 등록일.
- 각 평균·최소·최대·유효 표본 수를 표시한다. 등록일 누락·날짜 순서 이상은 해당 평균에서 제외한다.
- 실제 발주일·도착일·배송 지연 지표로 표현하지 않는다. 최초 예정일을 추정하거나 감사로그로 임의 복원하지 않는다.
- 예정일이 수정되었을 수 있으므로 항상 최종 예정일 기준임을 표시한다.

### 원료 사용

- 실적 확인 생산의 당시 ingredientsSnapshot.requiredQtyG만 계산상 사용량으로 집계한다. 현재 레시피로 재계산하지 않는다.
- 원료 ID 미연결은 이름으로 합치지 않고 생산·재료 항목별로 분리한다. 비활성 마스터/옛 이름도 이력을 유지한다.
- 실제 측정 사용량과 구분한다. 원육/봉투/영양제 차감·복원은 부호대로 순차감 집계하며 절댓값을 취하지 않는다. 계란은 출고 기록이다.
- 재고 변동일은 생산일과 다를 수 있다. 조정·전처리 이동을 생산 사용량으로 합산하지 않는다.
- 달력 일평균은 조회기간 전체 일수, 계산상 사용량의 생산일 평균은 해당 원료의 확인 생산 날짜 수, 변동일 평균은 해당 품목의 변동 날짜 수가 분모다.
- 제품별 계산상 원료 사용량과 근거 기록을 표시한다. 기록 기준 평균이며 실제 운영 전체 사용량을 보장하지 않는다.

## 조회·상태 및 한계

- 기존 pageResource/instantPageResource와 페이지 정리 구조를 유지한다.
- 탭·기간·집계 변경 시 이전 결과/Excel을 무효화하고 늦게 온 응답을 버린다.

- Excel 완료 전 페이지·조회조건·검색어·세션이 달라지면 내보내지 않는다.
- 마지막 입고 확인을 위해 종료일까지의 로그 이력을 읽는다. 완료 기준 표본 누락 방지를 위해 완료된 예정 문서를 읽고 완료일로 필터링한다. 이력 증가에 따른 읽기량은 향후 운영 성능 검토 대상이다.
- 날짜 필드가 없어 기간 쿼리에 걸리지 않는 과거 문서의 완전성은 이 화면만으로 검증되지 않는다.
- 운영 DB의 과거 이력 대조·운영 화면 확인·배포는 별도다.
