## 구현 경계

- `src/services/statsCorrections.js`: 별도 통계 결정의 원본·근거 필드 대조, Timestamp 정규화, 중복/충돌/변경 근거 차단. update/supersedes는 현재 지원하지 않고 명시 오류로 중단한다. 향후 철회 기능을 임의 우회하지 않는다.
- `src/services/statsLogic.js`: 기존 집계 수식에 앞서 검증된 사건 적격성을 반영. 생산 함수는 독립 유지. 화면·그래프·Excel·알림이 같은 투영을 사용.
- `src/pages/stats.js`: 정정 및 보류 사유 표시. 기간 밖 후속 근거를 놓치지 않도록 재료 통계에서 전체 이력과 stockLedger/statsCorrections를 읽는다. 첫 읽기 비용이 늘어나며 기존 세션 캐시를 유지한다. 제품 생산 탭은 이 두 컬렉션을 읽지 않는다.
- `src/services/statsAutomation.js`: 관련 품목의 미확정 입고/수동차감은 자동 판단 보류. 보류는 해결로 처리하지 않는다. 미확정 합계를 담는 주간 요약은 발송 후보에서 보류. AUTOMATION_VERSION과 수신자·에피소드·발송 중복키는 그대로 유지. 기존 컨펌 본문·확인·대화는 이 작업에서 수정하지 않았다.
- `firestore.rules`: statsCorrections는 생산앱 읽기만 허용, 클라이언트 create/update/delete 전부 금지. 운영 적용은 검토된 Admin 전용 create-only 도구를 사용한다.
- `scripts/readStatsRepair.readonly.mjs`, `prepareStatsRepair.mjs`, `statsRepairPlan.mjs`, `applyStatsRepair.mjs`, `verifyStatsRepair.mjs`: 읽기 스냅샷 → 명세 → 시뮬레이션 → 정확한 해시가 주어진 경우에만 create. 실행 시 원자적 재조회/검증과 재실행 무변화를 보장하며 stock/원본/컨펌 update/delete 경로는 없다.
- 백엔드 패키지 준비 도구는 이 저장소의 정본을 별도 output 폴더로 빌드한다. 재고관리 저장소에 쓰거나 배포하지 않았다.

## 운영 적용 전 순서

배포는 이번 실행 범위에 포함하지 않았다. 적용할 때는 최신 읽기 검증과 목록 해시 검증을 다시 통과해야 한다. 공유 Firebase 규칙은 기존 운영 정본에 statsCorrections 읽기 전용 블록만 병합·검증해야 하며, 이 저장소의 오래된 전체 규칙으로 공유 운영 규칙을 덮어쓰지 않는다.

화면·서버·정정 목록은 함께 전환해야 한다. 기존 서버에 닭염통 정정만 먼저 넣으면 표본 부족 대신 '정상'으로 기존 컨펌을 해결 처리할 수 있으므로 부분 적용하지 않는다. 관련 통계 알림의 발송 보류/재개와 기존 컨펌의 별도 정정 설명은 검토된 운영 전환 단계에서 수행한다. 현재 운영 설정과 실제 알림 상태는 변경하지 않았다. 설비 교체 주기·기존 최소재고 알림은 전환 대상이 아니다.
