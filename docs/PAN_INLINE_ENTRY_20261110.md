# 품목별 재고표: 빵판 입고 및 전처리 진입

사용자가 승인한 시안대로 상단에 종류별 총수량과 재고가 있는 품목별 수량을 함께 표시한다. 접힌 카테고리의 잔량도 요약에서 유지한다.

- 날짜 추가 시 입력창이 늘어서지 않는다. 빵판 단계가 있는 활성 레시피의 빵 칸을 눌렀을 때만 수량 입력창을 연다. 기존 행은 계속 입고분의 현재 잔량이며 직접 수정하지 않는다.
- 다른 칸 선택·카테고리 접기·실시간 화면 갱신 중에도 입력량을 Map으로 보존한다. 저장 시 입력한 품목만 처리한다. 담당자·날짜·비고를 기존 범위로 받으며 닫힌 날짜는 차단한다.
- 표 안 입고는 `saveBreadPanIncoming`에서 기존 `atomicStockOperation` 가드를 사용한다. 선택한 모든 신규 lot/입고 로그/활동 로그/원장을 한 트랜잭션으로 생성한다. 수량은 소수 두 자리, manualMovement receipt 메타데이터 및 원장 sourceLogId를 유지한다. 작업 ID와 요청 fingerprint로 재시도 중복을 막고 응답 불명 시 기존 readCommand가 자동 재전송을 차단한다.
- 날짜 추가 입고는 새로운 입력 경로다. 기존 입고 모달, 취소, 수동조정, 재고 계산은 변경하지 않는다. 새 입고 로그는 기존 취소 서비스에서도 연결 가능함을 검사했다.
- 동결판 칸은 기존 `showWorkRowModal`을 선택 품목으로 미리 채워 연다. 작업일은 오늘을 기본으로 하므로 과거 재고 칸을 눌러도 과거 입고분을 덮어쓰지 않는다. 실제 FIFO·환산·정수 실측 판수·차이 기록·원자 저장은 기존 `handleWorkRowSave`를 그대로 사용한다. 텐더는 원래 빵판 단계가 없으므로 기존 텐더 직접 입고 모달을 연다.
- 표 입력 중 전처리로 이동하면 먼저 저장/취소하도록 안내한다. 저장 중에는 입력을 잠그고 오류 시 행을 보존한다.

변경 파일: `src/pages/frozenPan.js`, `src/pages/frozenPanDesk.js`, `src/pages/panStockEntry.js`, `src/services/breadPanIncoming.js`, `src/frozenPanDesk.css`, `tests/panInlineEntry.test.mjs`.

검증 자료는 `output/pan-inline-entry/`에 보관한다. 실제 운영 재고를 테스트 입고하거나 차감하지 않는다. 테스트는 격리 데이터에서 수량/원장/취소/권한/마감/응답 유실을 검증하고, 운영 브라우저에서는 표시 및 입력 진입을 확인한다. Firestore rules, 권한 모델, 마감 로직, 기존 전처리 계산부 변경 없음.
