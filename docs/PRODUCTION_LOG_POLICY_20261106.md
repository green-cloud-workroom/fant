# 단순 생산 추가 기록의 이력 전용 처리 — 2026-11-06

사용자 승인: 단순 생산 추가 로그는 전체 이력에만 남기고 메인 알림과 마감 차단에서 제외한다. 실제 처리 알림 및 기존 재고 로직은 유지한다.

## 범위

- 실제 생산 등록 코드가 기록하는 `action: production`, `subAction: create` 조합만 이력 전용으로 분류한다. 메시지 문자열로 추측하거나 다른 생산 작업을 일괄 제외하지 않는다.
- 기존 기록의 원본·확인 상태를 수정하거나 삭제하지 않는다. 생산 등록 시 기록 생성과 재고 차감 트랜잭션도 그대로다.
- 메인 생산 로그, 모두 확인 대상, 마감 차단 판정과 날짜별 미확인 목록에서 해당 조합을 제외한다.
- 전체보기(10일)·히스토리(전체)는 계속 조회되며 해당 행은 노란 미확인 강조와 확인 버튼 대신 중립적인 `이력` 표시를 사용한다.
- 생산 수정/삭제, 알 수 없는 작업 유형, 자동 재포장, 전처리, 입고 예정, 입고 수량 차이, 긴급 입고 수정 및 나머지 기존 차단은 유지한다.

## 변경 파일

- `src/domain/activityLogPolicy.js`: 정확한 이력 전용 유형 판정.
- `src/pages/main.js`: 메인/일괄 확인 제외와 전체 이력 표시.
- `src/services/closingChecksLogic.js`: 마감 판정과 날짜별 조회에서 동일 기준 사용.
- `src/pages/settings.js`: 마감 설정 설명에 단순 추가 제외 명시. 설정값 변경 없음.
- `src/style.css`: 중립적인 이력 표시.
- `tests/productionLogPolicy.test.mjs`: 과거/현재 이력, 실제 작업 차단, 이력 보존, 일괄 확인 범위 검사.
- `scripts/productionCreateLogPolicyPatch.mjs`: 현재 배포된 서버의 정확한 생산 로그 필터에만 조건을 삽입한다. 모양이 바뀌었거나 이미 적용되면 거절한다.

## 서버 일치

현재 마감은 별도 `productionClosingCommand` Cloud Function에서 다시 판정한다. 확인한 원본은 `gcf-v2-sources-177376833232-asia-northeast3/productionClosingCommand/function-source.zip`, generation `1793646316712379`이다.

원본 27개 파일 중 `src/lib/closingChecksLogic.js`, `lib/lib/closingChecksLogic.js` 각각에 동일한 제외 조건 한 줄만 추가한 배포본을 준비했다. 나머지 25개 파일, 재고 스냅샷, 트랜잭션, 멱등성·버전·권한 검사는 바뀌지 않는다. 배포 대상은 이 함수 하나이며 `buildConfig.source`만 갱신한다. 배포 직전 원본 변경 여부를 검사하고, 완료 후 배포 소스 전체와 서비스 설정을 대조한다. 원본 출처 및 최종 리비전 증거는 아래 폴더에 보관한다.

## 검증

- 관련 회귀 테스트 **230/230 통과**, `npm run build` 통과.
- 내려받은 실제 서버 소스와 실행 파일에서 각각 60개 경우(총 120개) 판정 비교 통과. 다른 모든 순수 판정 함수는 동일하다.
- 로컬 실제 빌드 브라우저: 단순 추가 8건이 메인에 나타나지 않고 전체 이력에는 보존되는 것을 확인했다.
- 단순 추가만 남으면 마감 담당자 확인창에 진입한다. 실제 마감 저장은 실행하지 않았다.
- 실제 처리 알림 3종을 추가하면 마감 차단이 그대로 유지되고 생산 로그 차단의 날짜별 목록에는 생산 수정 1건만 나타난다.
- 브라우저 검증은 운영 DB와 분리된 예시 데이터이며 운영 계정 Chrome 연결은 도구 목록에 없었다. 운영 계정의 실제 마감 성공으로 보고하지 않는다.

증거: `output/production-log-policy/`의 테스트·서버 패치/배포 검증 JSON, 브라우저 캡처, Pages 공개 자산 검증 결과.
