# 메인 대시보드 로딩 개선 — 2026-11-06

## 변경

- `src/pages/main.js`: 생산표의 읽기 전용 미리보기를 오늘 로그·원료·계란 조회 완료보다 먼저 표시한다. 표시 날짜와 생산·레시피·완료 정보는 기다린다. 전체 모델과 작업 버튼은 기존의 모든 조회·마감 확인이 끝나야 활성화된다.
- `src/utils/stockAlertsView.js`: 메인 부족재고 요약은 기존 shell 구독 결과를 재사용한다. 모달 열기와 확인 완료는 계속 서버에서 새로 읽는다.
- `src/layout.js`: 상단바의 독립 조회를 병렬로 시작하고, 이미 읽은 부족 상태로 알림 전이만 기록한다. 알림 기록 전후 페이지와 로그인 세대가 유효한지 확인한다.
- `src/services/stockAlerts.js`: 알림 전이 저장을 분리했다. 화면 관찰 결과를 저장할 때 재고 전체를 재조회하지 않는다. 모달 확인의 최신 서버 조회 및 변경 감지는 유지한다.
- `tests/mainLoading.test.mjs`: 느린 로그 조회와 미리보기 분리, 요약 재조회 제거, 알림 저장 범위, 오래된 표시값으로 확인 완료 차단을 검증한다.

재고 수량 계산·차감·입고·마감 판정·권한·Firestore rules는 변경하지 않았다. 일반 생산 로그의 확인 의무도 이번 성능 변경에서는 그대로 유지했다.

## 생산 로그에 관한 별도 판단

일반 생산 추가 기록은 추적 이력으로 보존할 가치가 있다. 그러나 매 건 확인을 요구하는 메인 알림으로서의 효용은 낮다. 현재 미확인 생산 로그는 마감 조건과 연결되어 있으므로 화면에서만 숨기면 처리할 수 없는 마감 차단이 생긴다. 일반 등록은 전체 이력에 보존하고 메인은 조치가 필요한 예외 중심으로 바꾸려면 확인 의무와 마감 정책을 함께 조정해야 한다. 해당 정책 변경은 이번 성능 개선에 포함하지 않았다.
