# 영양제 품목별 작업 화면 — 2026-11-04

영양제 재고와 신청에서 제품 수에 비해 여백과 펼친 목록이 길어지는 문제를 줄인다. 재고는 제품 2열 선택 목록과 선택 제품의 단위별 작업 표로, 신청 작성은 동일한 제품 선택·단위 입력 구조로 변경했다. 좁은 화면에서는 제품 선택을 드롭다운으로 표시한다.

## 변경 범위

- `src/pages/supplement.js`: 제품명·단위 검색, 선택 제품 유지, 간결한 작업 표, 최근 변동 접기, 활성 하위 탭 표시. 기존 엑셀·전체 이력·입고·수동조정·비활성·권한 처리는 유지한다.
- `src/pages/supplementRequests.js`: 입력 DOM을 유지하는 제품 선택, 전체 신청 합계와 선택 내역 확인, 최신 재고의 읽기 전용 표시, 신청 상세 10품목 단위 페이지와 접힌 변경 이력. 신청·수정·취소·변경 요청·입고의 기존 서비스 호출, 편집 버전, busy 보호, 충돌 처리, 구독 정리는 유지한다.
- `src/style.css`: 영양제 전용 간격·표·선택 목록·모달·반응형 스타일.
- `tests/supplementCompact.test.mjs`, `tests/supplementRequests.test.mjs`: 제품 전환/검색/새로고침, 입력 보존, 비활성·삭제 SKU, 상세 페이지 보정, 최신 재고 표시와 늦은 응답 보호 검증.

운영 소스 `a5d4cfa`에서 분리한 작업폴더를 사용했다. 기존 신청 작업폴더의 미커밋 표시 라벨 수정은 선행 커밋 `95355b3`으로 보존했다. 원래 작업폴더의 파일과 Git 상태는 변경하지 않았다.

## 검증 및 경계

- `npm run test:supplement-requests`: 로컬 Firestore 에뮬레이터에서 요청·입고·중복 방지·부분 실패 재개를 검증. 처음에는 에뮬레이터 미실행으로 연결이 실패했고, 전용 에뮬레이터 실행 후 전체 통과했다.
- 영양제 재고 명령·폼 보호 및 신규 화면 회귀 검사 통과. 결과는 `output/supplement-compact/`에 보존한다.
- `npm run build` 및 `git diff --check` 통과.
- 실제 화면 모듈에 저장 기능 없는 로컬 데이터 어댑터를 연결하여 25제품/172품목 기준 1024×768, 390×844, 320×740 화면을 확인했다. 최종 1024×768 신청 창 본문은 clientHeight=scrollHeight=628로 내부 스크롤 없이 표시된다.
- 신청 창을 열면 기존 읽기 경로로 재고를 갱신한다. 조회 완료는 수량 입력을 교체하지 않으며, 조회 실패와 재고 문서 없음은 0봉과 구별한다.
- 운영 데이터 저장 검증은 하지 않는다. 재고 증감·자동차감·원자적 입고·Firestore Rules·권한 로직은 변경하지 않는다. 배포에는 기존 검증 배포 스크립트를 사용한다.
