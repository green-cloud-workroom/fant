# 통계 기반 자동화 — 구현 및 발송 차단 기록

작성일: 2026-10-22. 사용자 지시: 계획대로 단계별 구현, 기존 통계 계산·설비 교체 주기 유지, 실제 발송은 검증 이후.

## 현재 상태

- 생산관리 통계에 `알림 검증 · 발송 없음` 버튼 추가. 관리자·사무 권한에서 수동 실행한다.
- 최근 90일 원본에 대한 입고예정 등록 확인, 수량 확인, 제한된 소진 위험, 지난주 공유를 별도 모델로 제공한다. 통계의 선택 기간·검색·Excel 계산은 바꾸지 않는다.
- 팝업·저장 전 수량 확인·운영앱 컨펌 전달 경로는 구현했으나 `DELIVERY_RELEASED = false`로 차단한다. 화면에서 활성화할 수 없다.
- 공용 서버 코드 추가 및 빌드만 수행했다. Functions·Hosting·Rules 배포, 실제 컨펌/팝업 발송, 서버 설정 생성·활성화는 하지 않았다.
- 기존 최소재고 알림 및 설비 날짜 기반 교체 로직은 유지한다. 영양제 차감·생산 회차·환산표도 변경하지 않는다.

## 판단 기준과 보류

- 입고 간격: 최근 90일 중 서로 다른 입고 기록일의 간격 5개 이상. 마지막 기록에서 평균 간격에 따른 확인 시점 2일 전부터 유효 입고예정이 있는지 확인한다. 평균의 3배보다 오래된 패턴은 보류한다.
- 등록일수는 실제 발주일·도착일·공급사 배송 소요일로 사용하지 않는다. 현재 기능도 납품 지연을 확정하지 않는다.
- 수량: 이전 날짜의 같은 품목·단계·단위 표본 6건 이상, 중앙값 대비 10배 이상 또는 1/10 이하이면 확인 후보. 확정 오류가 아니다. 이미 정정한 입고량은 기존 정정 투영을 적용한다.
- 운영 대조에서 FIFO lot의 작은 부분 차감이 오탐 후보로 나타났다. 자동 lot 차감·복원은 수량 이상 비교에서 제외했다. 계산상 사용량은 같은 제품·생산 입력량·입력 단위끼리만 비교한다.
- 소진 위험: 계란·봉투의 현재 재고와 기록상 순사용만 비교한다. 양수 사용일 6일 이상, 최근 사용 14일 이내, 순사용 양수, 해당 재고 이력 수량·날짜가 유효해야 한다. 달력 일평균과 복원 부호는 기존 통계 기준을 따른다.
- 원육의 냉동·전처리·재포장 재고 및 영양제의 환산 단위는 대응 검증 전 소진 예측을 보류한다. 생산 미확인과 실제 계란 출고/봉투 차감은 서로 다른 근거이므로 구분한다.
- 기존 최소재고 미달이면 새 소진 위험 알림에서 중복 전달하지 않는다. 통계 추천은 기존 수동 기준을 자동 변경하지 않는다.
- 위 표본 수·10배·2일·14일은 현재 shadow 검증용 기본값이며 운영 타당성의 확정값이 아니다.

## 수신·중복·해결

- 부족·수량 확인은 사무팀·대표, 입고예정 확인은 사무팀 우선이다. 검증된 휴일 달력이 있어야 2영업일 미처리 시 대표에게 확대한다.
- 판타펫 회사 범위, 재직/수습, 사무팀 및 실제 Auth의 운영앱 역할·앱 접근·계정 활성 상태를 서버에서 확인한다. 대표는 별도 지정 UID를 검증한다. 생산관리 admin 권한을 대표라는 의미로 사용하지 않는다.
- 수신자를 모두 확인한 뒤 수신자별 비공개 컨펌을 한 트랜잭션에 생성한다. 한 명의 확인은 다른 수신자의 컨펌을 닫지 않는다.
- 고정 ID = 버전·문제·재발 회차·대표 확대 단계·악화 단계·수신자. 날짜 변경/재시도로 중복 생성하지 않는다. 기존 ID의 소유·문제 정보가 다르면 중단한다.
- 수량 차이의 자릿수 확대, 소진 추정 1일/반일 진입은 악화 단계로 구분한다. 단순 수치 흔들림은 새 컨펌이 아니다.
- 팝업은 수신자·브라우저 탭별 서버 임대를 사용한다. 열린 탭은 갱신하고 숨김/세션 변경/갱신 실패 시 팝업을 제거한다. 앱이 닫혀 있을 때 OS 푸시를 보내는 기능은 아니다.
- 운영앱 확인, 팝업 읽음, 문제 해결은 별개다. 원본의 유효 예정 등록·새 입고·수량 정정·취소·재고 회복 근거로만 해결한다. 표본 부족/새 조회에서 후보가 사라졌다는 이유로 해결하지 않는다.
- 해결된 원본에 연결된 요청은 취소 표시와 해결 문구를 추가하되 대화·확인 기록은 보존한다. 팝업 읽음도 해결 상태를 덮어쓰지 않는다.
- 주간 요약은 직전 월~일, 월요일 1회, `공유`로 보내는 경로이며 팝업은 없다. 활성화 이전의 수량 경고/주간 보고를 소급 발송하지 않는다.

## 발송 전 전환 조건

1. 실제 사무팀 명단·지정 대표를 읽기 전용으로 확인하고 회사/권한/계정 상태를 검증한다. 이름 추정이나 기존 현장기록의 사무팀장 한 명으로 대체하지 않는다.
2. 담당자가 확인 후보와 보류 사유·예상 알림 빈도를 검토한다. 원육·영양제 예측 보류는 그대로 유지한다.
3. 격리 환경의 실제 Firestore SDK·배포 중인 Rules·실제 역할 스냅샷으로 중복/수신함 조회/개인 확인 분리를 검증했다. 실제 수신자의 생산앱 권한이 없어 팝업은 차단되는 것이 확인됐다. 팝업 수신 경로를 확정한 뒤 장시간 여러 탭·임대 만료·세션 전환을 실제 브라우저에서도 확인해야 한다.
4. 미배포 코드를 검증하고 필요한 신규 핸들러/생산 UI만 배포한다. 공용 저장소의 무관한 dirty 변경을 포괄 배포하지 않는다.
5. `productionStatsAutomation/control`에 서버 전용 설정을 구성한다. 기본 없음=꺼짐. shadow만 켤 때도 실제 발송은 코드로 차단된다. 실제 발송 전에는 코드 검토·버전 확인·활성화일·대표 지정·검증된 영업일 달력을 준비하고, 사용자 지시대로 검증을 마친 뒤 활성화한다.

설정 예시(설명용, 운영 DB에 기록하지 않음): `mode:'shadow', shadowEnabled:true, deliveryEnabled:false`. 대표 전달을 위한 ownerUid, holidays, validatedHolidaysThrough 등은 실제 검증 후 구성한다. 검증 모드에서 기존 최소재고·설비 알림은 유지된다.
